## Observable requirements

- B1: bazaar.561.group MUST serve its own searchable human HTML at /, offering detail at /offers?source=...&id=..., and side-by-side comparison at /compare?source=...&id=... using repeated source/id pairs. Original IDs are URL-encoded; requests never supply new upstream URLs. Active item actions MUST be direct HTTPS URLs without credentials or private/local hosts; an unsafe original URL survives only as inert original-source evidence with no actionable URL. It MUST search actual current source offerings and show original product/offer identity, publisher, known seller, origin link, offered delivery kind, price/asset/unit where declared, freshness, consent scope and uncertainty. Unknown seller/payee remains unknown.
- B2: Bazaar MUST provide GET /discovery.json, /v1/discovery/search, /v1/discovery/compare and read-only POST /mcp with search_offers, get_offer, compare_offers. Human and machine views MUST consume the same request projection. Search supports q and source; compare returns the selected original records and explicit price-comparability result. No own catalog or duplicate offer authority is created.
- B3: The initial eligible sources are the original public shop.561.group/catalog.json and market.561.group/v1/catalog, whose publication/configuration custody is held by Causeway. Neither URL proves individual seller rights, external seller consent or independent control. Where rights are unqualified, display source-listed inspection/navigation and mark transaction qualification unavailable. Coming-soon items remain source-visible and non-buyable. Source hidden/private items MUST NOT be included.
- B4: Bazaar MUST retain book edition digest and artifact digests, original x402 SKU/cell/law, original invocation method/URL/schema, and original payment/recovery descriptors when present. It MUST NOT rename, merge or fabricate seller goods, mark a bare HTTP 402 as a paid delivery, or proxy purchases. A human follows the original Shop goods page; an agent inspects the original invocation. Different rails/units/assets are not price-comparable, even for the same edition, absent a separately qualified conversion contract.
- B5: Revoked, expired, contested, unknown or unsupported external membership MUST NOT produce an admitted listing. Current house-publication status means only publisher-authorized source projection; it is not provider verification. External discovery is admitted only from source-owner grant with publication/representation scope, revision, expiry and revocation evidence. Public provenance redacts private consent material while preserving independently verifiable evidence locators.
- M1: market.561.group MUST serve an observation/navigation HTML homepage, GET /markets/discovery.json, /markets/observations, /markets/venues and read-only POST /markets/mcp. It MUST link the actual Bazaar and Shop, and observe at least two unrelated external market publishers with source date, request time, source URL, method, measurement scope, units, coverage and uncertainty. It MUST NOT substitute the merchant offer catalog for this Market role.
- M2: Initial external observations read 402 Index's published /api/v1/health and MPP's published /api/services. The former supplies publisher-reported endpoint/service/provider/health counts; the latter supplies a count of entries and declared endpoints in the complete fetched curated catalog. These populations overlap and MUST NOT be summed, equated with independent Shops, attributed to Group income, or treated as proven settlement/delivery. Unknown liquidity, demand, transactions, revenue and net contribution remain explicit null/unknown, never zero. Original external source links remain available.
- P1: Existing market x402 catalog, well-known metadata, ActivityPub actor/outbox, merchant MCP, payable routes, request bodies, SKU, payee, settlement/recovery and installed state MUST remain served by the original merchant handler at their original paths and origin. A new navigation front controller serves only the homepage and exact /markets/ observation paths; every other request is forwarded intact to the existing immutable merchant Worker through its existing-platform service binding. The original merchant /mcp remains unchanged; observation MCP has its distinct path. No payable merchant endpoint is served under Bazaar merely because it shares code.
- P2: Existing Shop /, /goods/*, /catalog.json, checkout/account/gift/fulfillment and accepted artifact identities MUST remain under its original Worker and storage. Preserve the currently installed behavior of /mcp; this does not assert that Shop MCP is live. The independently observed initial agent resource is /catalog.json. This slice does not require Shop source changes, purchases, unarming checkout or a second fulfillment store.
- R1: Source requests are read-only, finite, allowlisted HTTPS without credentials, redirects or user-controlled targets. Each observation carries original source bytes digest, fetch clock, source clock when supplied, and complete/incomplete state. A failed source yields an explicit partial result alongside surviving sources. All unavailable sources yield 503 for dynamic search/readouts, while the source directory remains inspectable. A timeout, stale cached value or incomplete body MUST NOT be called a fresh current quote.
- R2: Public query input cannot set source configuration, actor, consent, payee, clock, budget, release identity or upstream request headers. Mutating Bazaar methods and unknown MCP tools refuse. Reads create no order, charge, grant, seller signup or hidden referral fee. Public source visibility does not authorize external seller contact or purchase.
- R3: Release receiving MUST independently verify DNS, canonical HTTPS/TLS, each origin's resource identity, source/deployed revision, working search/detail/comparison, machine discovery/MCP and meaningful positive/alternate/refusal cases. Domain attachment, HTTP 200 or a landing page is insufficient. Preserve original merchant/Shop smoke checks and before/after fingerprints without paying.
