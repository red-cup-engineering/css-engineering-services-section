## Runtime views

Market request / or one exact /markets/ endpoint → navigator → fixed public observation readers or existing merchant binding GET catalog → pure observation model → TUFTE HTML or same JSON/MCP result. Every other Market request → MERCHANT.fetch(originalRequest) → original merchant response. Do not reconstruct the URL, consume the body or normalize signed headers in the forwarding branch. Root replacement is intentional; original merchant discovery and commerce paths remain original.

Bazaar human/search/detail/compare/MCP request → navigator → fixed Shop public catalog and original merchant read-only catalog via service binding → per-source identity-preserving projection → shared search/detail presentation. Neither source URL means independent enterprise control. Comparison is a fact table, with a reason when unit/rail/asset/outcome differs; no manufactured best-price or authority. Source failure removes its current results and exposes exact partial coverage.

Market external observations are original 402 Index /api/v1/health and MPP /api/services, currently published as public discovery interfaces. Original dated bytes are summarized as publisher testimony. Do not publish their individual sellers as consented Bazaar members. Market links to each original market and observes Bazaar with its explicitly house-only coverage. The same external inventory may occur in both markets; aggregation cannot infer distinct population or sales.

## Alternatives and quality scenarios

- Rebuild/redeploy the existing merchant closure: rejected for this slice because it couples navigation to approximately sixty unrelated dependencies and an unreceived publication. Original merchant changes remain their original work.
- Redirect all three hosts to one merchant or static landing pages: rejected; no independent useful role or resource identity.
- New copied catalog: rejected; it duplicates original mutable authority and loses revocation/edition/payment provenance.
- Selected front controller: preserves exact merchant runtime and storage while adding a small independently testable navigation closure. Tradeoff: one explicit service binding and one additional Worker deployment; verify the binding preserves canonical Request/Response bytes.

When the merchant receives a signed POST or recovery retry during rollout, the navigator forwards the original Request exactly once and returns the original response, with no read, clone, purchase retry, mutation or caching. Acceptance: source fake-binding byte assay plus original unsigned live challenge/catalog fingerprints and installed release identity; no real payment is implied.

When one discovery publisher fails, healthy sources still answer within the configured deadline, a source-specific refusal appears, and current listing/quote status is not invented. When all fail, dynamic data returns 503 with inspectable source statuses. A stale memory snapshot may be displayed only with stale labels and cannot qualify a current offer.

When a public request supplies a private URL, fake source clock, consent override or host, the request is refused before network I/O. Fixed source configuration and original source editions determine custody. New read operations require no credentials or write grants. Third-party signup/consent and any optional paid service remain separately admitted.
