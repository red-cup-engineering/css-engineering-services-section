What we’re building

One canonical RDF graph that stores: data, interpretations, ontologies (OWL), and constraints (SHACL).

Interpreters (reasoner, validator, indexers, embedders) that read/write RDF triples and produce projections (search, vectors, caches).

Everything swappable because all contracts are standard: RDF, SPARQL, SHACL, OWL, PROV-O.

Core vocabularies (all RDF)

Your domain ontology: Expression, Statement, Agent, Place, etc.

PROV-O for provenance of claims/verifications.

OWL axioms for meaning (classes, properties, restrictions).

SHACL shapes for constraints (soft→hard).

(Optional) RDF* / SPARQL* so “statements about statements” are tidy when you need nested/functional predicates.

Best complete stack (open-source, swappable)
1) Canonical graph store (truth & rules)

Apache Jena Fuseki (TDB2 storage)

Why: mature, open, SPARQL 1.1, RDF/OWL/SHACL friendly, easy to run.

Stores everything: your data triples, OWL axioms, SHACL shapes, PROV-O traces, and even determinations as RDF.

Swaps: Blazegraph, GraphDB Free, Eclipse RDF4J.

2) Reasoning & validation (operational semantics)

OWL reasoner (Jena built-ins or Pellet/HermiT if needed) → derive new triples, type inferences.

SHACL validator (Jena SHACL) → evaluate data vs. shapes with severities: info → warning → violation.

Both run as services that: read RDF → write RDF (no side formats).

3) Event & provenance (history of knowing)

Postgres (append-only events)

Records each change/ingest/verification with minimal metadata; mirrors into the graph as PROV-O.

Gives durable replay, idempotence, and audit trails.

Swap: XTDB if you prefer bitemporality at the datastore.

4) Search projection (pragmatic retrieval)

OpenSearch

Index selected RDF literals (labels, bodies, tags) and IRIs as fields.

Keep IRIs to round-trip back to the graph.

Just a projection; source of truth is RDF.

Swap: Meilisearch/Typesense.

5) Vector projection (fuzzy similarity)

Qdrant

Compute embeddings from selected literals (e.g., schema:text, your:body).

Store vector + the originating RDF subject IRI.

Filter by metadata carried from the graph (time, author).

Swaps: Milvus, Weaviate, pgvector.

6) Object storage (raw artifacts)

MinIO (S3-compatible)

PDFs, images, raw text exports; store object IRI in the graph.

7) Pipelines & orchestration

NATS (event bus): “graph updated,” “verify received,” “embed needed,” etc.

Temporal (workflows): resilient, replayable jobs—ingest → reason → validate → index → embed → write back RDF (e.g., determinations).

Swaps: RabbitMQ + Airflow/Prefect.

8) Fusion API (one interface to rule them all)

GraphQL gateway in front of:

SPARQL endpoint (graph queries),

OpenSearch (text),

Qdrant (vectors),

with logic to compose/merge results and always return IRIs + provenance.
Purpose: keep the UI stable while backends can be swapped.

9) Identity & policy

Keycloak (OIDC) for auth.

OPA if you need attribute-based field/shape policies (e.g., who can assert constraints).

10) Authoring & exploration UI

Next.js + TipTap (ProseMirror) editor with inline entity linking (IRIs).

Cytoscape.js for graph neighborhood/paths.

“Why” panel that shows: SPARQL matches, SHACL state, inferred triples, vector neighbors, and PROV-O provenance.

Live SHACL feedback during editing (soft→hard ladder visible).

11) Observability & ops

OpenTelemetry, Prometheus/Grafana, Loki; Docker Compose for dev; K8s later.

How the system “thinks” (all RDF, operationalized)

You assert data (triples) via the UI/SPARQL.

Reasoner derives inferences (OWL), validator runs SHACL shapes (constraints live as triples).

Projections update:

OpenSearch indexes selected literals,

Qdrant stores embeddings,

Postgres logs events (which also become PROV-O in the graph).

Verifications (human/sensor) are recorded as PROV-O activities and may emit new RDF (e.g., increasing a confidence statement, or proposing a stricter SHACL shape).

Soft→hard: as supporting RDF grows, you promote shapes (change sh:severity) or add OWL restrictions. That promotion is itself RDF with provenance.

Queries go through GraphQL → SPARQL + (optional) search/vector → merged results with IRIs and “why.”
